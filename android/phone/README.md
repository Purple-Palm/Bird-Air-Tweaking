# Bird Air — приложение для телефона (`:phone`)

Держит связь с самокатом в фоне, с выключенным экраном, и показывает живые данные: скорость, режим,
**полосу мощности** (вправо оранжевая тяга из батареи, влево синяя рекуперация в батарею, ноль по
центру, шкала — скользящий максимум, как на странице), **графики** мощности, скорости и напряжения,
батарею с запасом хода, **предупреждения** о батарее, поездку, энергию и свой одометр. Каждое новое
значение сразу уходит на экран и на часы (модуль `:wear`).

## Сборка и установка

```sh
cd android
ANDROID_HOME=/root/android-sdk ./gradlew --no-daemon :phone:assembleDebug
adb install -r phone/build/outputs/apk/debug/phone-debug.apk
```

Телефон и часы подписаны одним ключом `android/debug.keystore` и имеют один applicationId
`io.github.purplepalm.birdair` — без этого Wear Data Layer не соединит приложения.

Версия — из свойств Gradle: `-PversionCode=<целое>` (по умолчанию 1), `-PversionName=<строка>`
(`dev`), `-PgitSha=<коммит>` (пусто) → `BuildConfig.VERSION_CODE`, `VERSION_NAME`, `GIT_SHA`. Их
видно в «Настройках»; обновление в приложении сравнивает только `versionCode`.

В APK вшит `decoders/current.json` из репозитория; при запуске приложение берёт
`https://purple-palm.github.io/Bird-Air-Tweaking/decoders/current.json` (5 с) и, если там версия выше,
сохраняет его и использует.

## Первый запуск

1. «Разрешить»: «Устройства поблизости» (поиск и связь по Bluetooth) и «Уведомления» (значок
   поездки со скоростью, тягой и кнопкой «Отключить», предупреждения о батарее).
2. «Подключить» → поиск 10 с по сервису `0xFFE0` → нажать свой самокат. Адрес запоминается, дальше
   «Подключить» соединяется сразу; «Выбрать другой» ищет заново. Приложение Bird на телефоне
   должно быть закрыто: руль держит одно подключение.
3. Карточка «Работа в фоне»: «Разрешить работу в фоне» (без оптимизации батареи) и на Samsung —
   Настройки → Батарея → Ограничения фоновой работы → «Никогда не засыпающие приложения» → Bird Air.

После подключения работает служба переднего плана (тип connectedDevice, partial wake lock, пока
связь нужна): каждые 2,5 с она шлёт `+SVGT=?` (руль шлёт кадры ~4,5 с после команды), при обрыве
переподключается через 1, 2, 4, 8, 10 с. Обрывом считается и выключение Bluetooth (Android об этом
может не сообщить), и 10 с без единого кадра при живом подключении. Если 10 минут нет никаких данных
(самокат выключен, а «Отключить» забыли), служба останавливается сама и оставляет уведомление «Связь с
самокатом остановлена». «Отключить» (в приложении или в уведомлении) всё останавливает, сохраняет лог и,
если включена автоотправка, отправляет его.

## Живые данные и задержка

Таймера 250 мс больше нет. Уведомление BLE (поток Binder) только пишет запись в лог и разбирает кадр
под замком трекера (`LivePipeline.onRx`, микросекунды) и будит один поток-публикатор
(`Dispatchers.Default`, канал CONFLATED): тот снимает снимок и сразу кладёт его в `StateFlow` экрана и
в очередь часов. Если за время публикации пришло ещё несколько уведомлений, следующая публикация одна,
с самыми свежими значениями. Без новых данных публикация идёт раз в секунду (пульс: «нет данных»,
состояние связи, часы слышат телефон). Уведомление «Поездка» — примерно раз в секунду, как раньше.

Бюджет задержки (от уведомления BLE до пикселя):

| Звено | Было | Стало |
| --- | --- | --- |
| уведомление → снимок | 0–250 мс (ждал тик) | < 1 мс (тест на реальных потоках: медиана 0 мс, максимум 7 мс) |
| снимок → кадр экрана | ≤ 8 мс (120 Гц) | ≤ 8 мс |
| полоса догоняет значение | tween 150 мс | пружина: треть пути за ~25 мс, 98 % за ~110 мс; «Плавная анимация» выкл — сразу |
| телефон → часы | 0–250 мс + Data Layer | сразу (если отправка в пути — следующая с самым свежим), не чаще 25 в секунду, + Data Layer (обычно 20–60 мс) |

Сама мощность: «Быстрая мощность» (по умолчанию вкл) — ток и мощность по просадке напряжения
(`Telemetry.currentFastA` / `powerFastW` из `core/FastPower`), свежие на каждом кадре BMS (~3,2 в
секунду); ток BMS обновляется раз в секунду и запаздывает на ~0,6 с. Её показывают полоса, число,
уведомление, график и часы; без неё (или пока оценки нет) — мощность BMS. Шкала полосы (`peakW` в
публикуемом снимке) считается по той мощности, которую показывают, тем же правилом, что на странице.

На часы вместе со снимком уходят оба переключателя: `extras["fast"]` и `extras["smooth"]` = 1.0 / 0.0.

## Графики

Карточка «Графики», как на странице (`drawSeries` / `drawPowerChart`): мощность по времени — тяга над нулём
оранжевым, рекуперация под нулём синим, линия нуля, ось времени; под ней скорость и напряжение на той же
оси. Окно «1 мин / 5 мин / 15 мин / вся поездка» (запоминается). Коснись графика и веди пальцем: время,
мощность, ток, напряжение и скорость в тот момент, перекрестие на всех трёх графиках; «×» убирает. Метки
(«Метка» в карточке «Лог») — вертикальные линии. Под графиками — энергия за окно: потрачено, возвращено,
Вт·ч/км (по одометру приложения), средняя мощность.

История — кольцевой буфер `SampleRing` в процессе: по точке на каждый снимок с новыми данными (≈ частота
кадров, 15–20 в секунду), 144 000 точек (2 ч при 20/с), дальше старые уходят. На экран — минимум и
максимум на каждый пиксель ширины (`Downsample.minMax`, пики не пропадают ни в каком окне), разрывы
больше 3 с не соединяются. Пересчёт на фоне, перерисовка не чаще 5 раз в секунду. Своя отрисовка на
Compose Canvas, без библиотек графиков.

## Предупреждения и запас хода

Из `core/BatteryAdvisor`: «Заряд на исходе» / «Сейчас отключится» (напряжение под нагрузкой у отсечки),
«Батарея греется» / «Батарея перегрета» (≥ 50 / ≥ 55 °C). На экране — плашка сверху (красная — опасно,
жёлтая — внимание) с числом и тем, что делать. Напряжение «под нагрузкой» телефон берёт сам
(`LoadSag`): минимум за 30 с при быстром токе ≥ 5 А — у советчика это последнее напряжение при токе BMS
≥ 5 А, а ток BMS отстаёт, и после газа туда попадает отскочившее напряжение (35–36 В). Уведомление
«Предупреждения» (свой канал, высокий приоритет, вибрация) срабатывает, когда предупреждение появилось
или стало опаснее, но одно и то же (предупреждение и уровень) — не чаще раза в 5 минут
(`WarningAlerts`); стало слабее — текст меняется тихо; всё прошло — уведомление убирается. Активные
предупреждения уходят на часы в `Telemetry.warnings`. Если приложение на часах открыто или едет с тобой
(последний hello с версией не старше 45 с, `Versions.watchBuzzes`), оно вибрирует само, и уведомление
остаётся только на телефоне (local-only) — на запястье одна вибрация, не две; иначе Wear OS показывает
его на часах.

Рядом с батареей — запас хода до отключения (не до 0 % BMS): «≈ 4,2 км / 2,6 mi до отключения» и по
какому расходу посчитан.

## Одометр приложения

Одометр руля теряет пробег при выключении питания (начинал снова с 1434,2 км, потом 1445,0). Приложение
ведёт свой (`core/AppOdometer`): «Одометр (приложение)» и рядом «по рулю». Состояние хранится в настройках
приложения (раз в 5 с, когда изменилось, и при отключении/обрыве). «Настройки» → «Исправить, км» → «Задать»
ставит своё значение (дальше считает от него), «Взять с руля» — текущее число руля.

## Что приложение пишет в самокат

Только в `0xFFE1` и только шесть строк: `+SVGT=?` (пульс), `+MODE=1/2/3`, `+HLGT=0/1`. Режим и
фара — только по нажатию в «Управлении» при включённом «Разрешить команды» (выключен при каждом
запуске). Всё идёт через одну функцию `ScooterLink.write()` и `WriteGuard`: `KEY?` (`AE 4B 45 59`)
где угодно в данных, OTA/DFU-характеристики, любые другие байты и характеристики отклоняются;
проверка повторяется прямо перед вызовом радио. Графики, предупреждения, одометр, обновление и логи
ничего в самокат не пишут.

## Логи

Вся сессия (от «Подключить» до «Отключить», с переподключениями) пишется в формате
`birdair-lab-log` v1 (`logs/README.md`), всегда обезличенной, в `filesDir/logs/<имя>.json.gz` каждые
5 минут и при обрыве/отключении. Длинная поездка делится на **части** по 250 000 записей
(`LogRecorder.rotate`, до обрезки дело не доходит, `"trimmed"` остаётся `false`): каждая часть — свой файл,
сохраняется и отправляется как отдельный лог, первая запись следующей — «продолжение лога <имя
предыдущей>», в коммите — «часть N».

**Описание лога** — поле в карточке «Лог», как «Подпись в имени файла» на странице: пока запись ни разу
не отправлялась, имя файла — `<YYYYMMDD-HHMMSS>-<транслит описания>` (имя и адрес самоката из него
вырезаются); при первой отправке имя фиксируется, дальше та же запись перезаписывает тот же файл, хоть
описание и поменяли. Весь текст описания идёт в `"note"` лога и телом в сообщение коммита (без имени
самоката). Описание переходит на следующую запись — поменяй, если поездка другая.

**Метка** — текст и кнопка: запись `mk` в идущий лог с текущим временем (до 60 знаков) и линия на графике.

**Неотправленные логи** — файлы из `filesDir/logs`, которых нет на GitHub или которые изменились после
отправки (что и куда ушло, приложение помнит в своих настройках, отдельно от токена). «Отправить все» —
по порядку, от старых; у каждого — «Поделиться». Файл старой сборки, который уже лежит на GitHub под тем
же именем, только отмечается (совпал git-sha) или перезаписывается — копий «-2» не появляется. Удаляются
сами только отправленные файлы сверх 40 (неотправленные — сверх 120).

GitHub, как на странице: owner / repo / ветка / папка (по умолчанию Purple-Palm / Bird-Air-Tweaking /
main / logs) и fine-grained токен с правом Contents: Read and write. Токен хранится только в
приватных настройках приложения, не показывается, не попадает в логи и в резервные копии.
Файл — `<папка>/<имя>-app.json.gz`, повторная отправка перезаписывает его (по sha
из прошлого ответа; если sha устарел — ответ потерялся или файл меняли в репозитории, — берёт текущий и
повторяет). «Отправлять лог сам» — каждые 5 минут, пока есть связь, после обрыва (не чаще раза в
минуту) и сразу, как закрылась часть.

## Обновление в приложении

При запуске (если прошло больше 10 минут с прошлой проверки) и раз в сутки приложение читает
`https://github.com/Purple-Palm/Bird-Air-Tweaking/releases/download/android-latest/version.json`
(`{"versionCode": 57, "versionName": "0.57", "sha": "…"}`, его выкладывает CI). Если там `versionCode`
больше установленного — сверху «Есть обновление (v57) → Обновить»: `bird-air-phone.apk` из того же релиза
скачивается в кэш, проверяется (это Bird Air и версия новее) и открывается системный установщик
(FileProvider, `REQUEST_INSTALL_PACKAGES`). В первый раз Android попросит «Установка неизвестных
приложений» для Bird Air — кнопка «Разрешить установку» ведёт туда, после возврата установка продолжается.
Ставится поверх, с тем же ключом: настройки, адрес самоката и логи остаются. «Настройки» → «Проверить
обновления» — вручную, там же версия приложения и sha сборки.

Версия часов: если часы шлют её в «hello» (см. ниже), карточка «Часы» её показывает и подсказывает
«обнови часы: bird-air-watch.apk через Bugjaeger», если там сборка старше телефонной.

## Связь с часами (контракт для `:wear`)

- Телефон → часы: `MessageClient`, путь `Wire.PATH` = `/birdair/telemetry`, данные
  `Wire.encode(Telemetry)` всем подключённым узлам, пока работает служба: каждый новый снимок сразу (пока
  отправка в пути, ждёт только самый свежий), не чаще раза в 40 мс, и не реже раза в секунду. `peakW` —
  шкала показываемой мощности, `extras["fast"]` / `extras["smooth"]` — переключатели «Быстрая мощность» и
  «Плавная анимация» (1.0 / 0.0), `warnings` — активные предупреждения (у battery_low `value` —
  напряжение под нагрузкой по `LoadSag`). При «Отключить» уходит последний снимок с `link = IDLE`,
  `streaming = false`.
- Часы → телефон: `Wire.HELLO` = `/birdair/hello`. Данные — пусто или UTF-8 JSON
  `{"app":"wear","versionCode": 57, "versionName": "57-1a2b3c4"}` (понимает и `vc`/`vn`, и строки
  `versionCode=57`). Часы шлют его при открытии, каждые 5 с без данных и каждые 30 с, пока данные идут.
  Телефон отвечает сразу текущим снимком (`WatchListenerService`, работает и без запущенной службы) и
  сразу добавляет эти часы в рассылку.
- Телефон объявляет capability `birdair_phone` (`res/values/wear.xml`).
- «Открыть на часах»: `RemoteActivityHelper.startRemoteActivity` с
  `Intent(ACTION_VIEW, Uri.parse("birdair://open"))` + `CATEGORY_BROWSABLE`. В манифесте часов у
  `MainActivity` нужен фильтр:

  ```xml
  <intent-filter>
      <action android:name="android.intent.action.VIEW" />
      <category android:name="android.intent.category.DEFAULT" />
      <category android:name="android.intent.category.BROWSABLE" />
      <data android:scheme="birdair" android:host="open" />
  </intent-filter>
  ```

## Тесты

```sh
ANDROID_HOME=/root/android-sdk ./gradlew --no-daemon :phone:testDebugUnitTest :phone:lintDebug
```

JVM-тесты: `WriteGuardTest` (белый список, KEY?, OTA/DFU, только FFE1), `GitHubApiTest` (запрос PUT,
sha, пути, тексты ошибок, расписание автоотправки по частям), `TextsTest` (числа по-русски,
тяга/рекуперация, текст уведомления, в том числе из кадров через декодер v5), `GattQueueTest` (одна
операция за раз, таймауты, обрыв), `TimingTest` (переподключение, пульс, выбор декодера),
`PipelineTest` (поездка 14.10 через конвейер: каждый кадр с новым значением опубликован до возврата из
`onRx`, каждый кадр BMS дошёл до экрана; задержка на реальных потоках; пульс без данных; шкала быстрой
мощности), `SpringTest` (пружина: 98 % за 95–125 мс при 60/90/120 Гц без перелёта, не перескакивает
цель при движущейся цели, точна при любом шаге), `ChartDataTest` (min/max на столбец сохраняет пики,

описания и числа записей из файла, git-sha), `VersionsTest` (version.json, сравнение версий, когда
