# Логи

Сюда страница кладёт логи кнопкой «Отправить лог в GitHub», сюда же сохраняют
`tools/parse_btsnoop.py` и `tools/ble_logger.py`.

Имена: `YYYYMMDD-HHMMSS-<метка>.json`, большие — `.json.gz`, очень большие режутся на
части `...-part1of3.json.gz`. Время — начало записи по часам телефона.

Формат `birdair-lab-log` v1:

```json
{
  "format": "birdair-lab-log", "version": 1,
  "startedAt": "2026-10-14T19:02:11.000Z",
  "device": { "name": "scooter", "id": "scooter" },
  "note": "вдвоём до отсечки, FLY",
  "gatt": [{ "uuid": "<service>", "chars": [{ "uuid": "<char>", "props": { "read": true, "notify": true } }] }],
  "decoder": { "json": false, "fields": [] },
  "part": { "id": "…", "index": 1, "count": 3 },
  "entries": [
    { "t": 1234, "k": "rx", "s": "<service>", "u": "<char>", "h": "5A A5 0B 25 …" },
    { "t": 1300, "k": "mk", "n": "Газ" }
  ]
}
```

`gatt[].chars[].danger: true` ставит `parse_btsnoop.py` у характеристик OTA/DFU (страница
проверяет это сама). У логов из `parse_btsnoop.py` без обнаружения сервисов вместо UUID стоит
`handle-0x0012`.

`note` — описание лога, которое вписал владелец (необязательное, строка; пустое не пишется).
Из него же — подпись в имени файла: транслитерация, `[a-z0-9-]`, не длиннее 40 символов (как
поле «Подпись в имени файла» на странице), например «Вдвоём до отсечки» → `vdvoem-do-otsechki`.
`tools/birdlog.py` его сохраняет (`clean_note`), обезличивание убирает из него имя устройства,
`analyze_log.py` печатает.

Приложение не обрезает длинную запись, а режет её на логи подряд (`LogRecorder.rotate`, около
250 000 записей): у следующего своё `startedAt` и имя файла, его первая запись —
`{"k": "sys", "n": "продолжение лога <имя предыдущего без .json.gz>"}`. `"trimmed": true` —
старые записи выброшены (так было до разбиения на логи).

`t` — миллисекунды от начала записи. `k`: `rx` — уведомление от самоката, `rd` — чтение,
`tx` — запись в самокат, `mk` — метка, `sys` — служебная строка, `gps` — скорость телефона по
GPS: `v` — м/с, `a` — точность, м (координат в логе нет никогда). Поля `part` нет, если лог
целый. Репозиторий публичный: логи отправляются обезличенными (имя и id устройства →
`scooter`).

Кадры контроллера. После любой команды «+…» с телефона руль шлёт в `0xFFE1` кадры
`3A адрес команда длина данные[длина] сумма16-LE 0D 0A`, сумма = (адрес + команда + длина +
сумма данных) & 0xFFFF. BLE режет кадр на несколько `rx`, иногда теряет первый `3A`. Собирает
их `tools/uart_frames.py` (то же делает страница, если в декодере `"framing": "colon-sum16"`;
тогда поля декодера читают целые кадры, смещения от `3A`, а `mask` у поля выделяет биты:
`(raw & mask) >> нули справа в mask`). `analyze_log.py` разбирает такую характеристику по
кадрам, а записи `tx` вида `+MODE=n` / `+HLGT=n` считает метками. Запись `AE 4B 45 59 …`
(«KEY?») останавливает кадры и уводит руль в ошибку 37 до перезагрузки — её не слать
(`birdlog.DANGER_WRITES`, инструменты помечают её «ОПАСНО»).
