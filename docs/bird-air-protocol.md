# Протокол Bird Air (VA00020) — что известно

Разобрано из открытой распакованной сборки приложения Bird для Android
(`co.bird.android` 4.188, репозиторий `darkneuralnet/red`, формат apktool/smali) и из
реального лога самоката. Это личный самокат владельца; цель — чтение телеметрии и
диагностика. **OTA/DFU команды сюда намеренно не вынесены и в самокат не отправляются.**

Каждая строка ниже помечена: ✓ проверено по коду, ? требует подтверждения на живом самокате.

## BLE

- Сервис `0xFFE0`, характеристика `0xFFE1` — одна на всё: запись без ответа (write without
  response) и уведомления (notify). ✓ (`GattUuid.smali`: `BIRD_AIR_SERVICE` = `0000ffe0-…`,
  `BIRD_AIR_COMMAND_UUID` = `0000ffe1-…`).
- Модуль — прозрачный UART-мост (Telink TLSR8266 / Wi-linktech WLT8266BM). Руль шлёт в него
  AT-команды для настройки; при подключении без приложения он пересылает их наружу — отсюда
  `AT+SETNAME=…`, `AT+RESET` в логе. ✓ (лог владельца).
- **Шифрования нет.** Для Bird Air `BlePayloadEncryptor` — заглушка: `encrypt`/`decrypt`
  возвращают данные как есть. ✓ (`BlePayloadEncryptor$DefaultImpls`,
  `BleScannedVehicle$payloadEncryptor$1`).
- Запись длиннее 20 байт режется на куски по 16 байт с интервалом ~100 мс. ✓
  (`VehicleConnection$DefaultImpls.writeData`).

## Телеметрия в рекламном пакете (чтение без подключения)

Заряд, режим, пробег и версия прошивки Bird Air **вещает в рекламе** (manufacturer-specific
данные), то есть их видно сканером без подключения, рукопожатия и серверов Bird. ✓
(`Ot4.h` → конструктор `BirdAirBleScannedVehicle`).

Формат payload после 2-байтового company id, порядок little-endian:

| смещение | размер | поле | примечание |
| --- | --- | --- | --- |
| 0 | 2 | версия прошивки | u16 LE ✓ |
| 2 | 1 | заряд | u8, проценты ? |
| 3 | 1 | режим | см. ниже ✓ (байт), маппинг ? |
| 4 | 4 | пробег/одометр | u32 LE, через `mS.c()` — коэффициент уточнить ? |

Режим (байт по смещению 3), маппинг зависит от модели (`kU0.a`): для «es»-моделей
`0 → POWER_SAVING, 1 → NORMAL, иначе → SPORT`; для прочих — другой маппинг по строке модели.
Для VA00020 нужно подтвердить на живом самокате сопоставление с TAKEOFF/GLIDE/FLY. ?

На телефоне в Chrome рекламные manufacturer-данные через Web Bluetooth не прочитать
(`watchAdvertisements` в стабильном Chrome на Android недоступен). Их показывает **nRF
Connect** (поле Manufacturer data) или любая плата-сканер (ESP32, nRF). `tools/decode_adv.py`
разбирает эти байты по таблице выше.

## Команды (для будущих кнопок; не приоритет)

Все управляющие команды Bird Air — короткие ASCII-строки, пишутся в `0xFFE1`. ✓
(`Command.smali`, массивы байт в `<clinit>`):

| действие | байты | строка |
| --- | --- | --- |
| режим TAKEOFF | `2B 4D 4F 44 45 3D 31` | `+MODE=1` |
| режим GLIDE | `2B 4D 4F 44 45 3D 32` | `+MODE=2` |
| режим FLY | `2B 4D 4F 44 45 3D 33` | `+MODE=3` |
| фара выкл | `2B 48 4C 47 54 3D 30` | `+HLGT=0` |
| фара вкл | `2B 48 4C 47 54 3D 31` | `+HLGT=1` |
| версия прошивки дисплея | `2B 53 56 47 54 3D 3F` | `+SVGT=?` |
| версия железа дисплея | `2B 48 56 47 54 3D 3F` | `+HVGT=?` |

Это те же три заводских режима, что переключает кнопка на руле, и та же фара. Запрос версий
(`+SVGT=?`, `+HVGT=?`) — чистое чтение, ответ приходит уведомлением по `0xFFE1`.

## Рукопожатие (барьер доступа самоката)

Перед привилегированными командами приложение шлёт «вызов» и код:

- «вызов»: `AE 4B 45 59 3F D6` (`AE` + `KEY?` + `D6`). ✓
- код: `AE 4B 45 59` (`AE KEY`) + два байта `[код, контрольная сумма]`, где
  `контрольная сумма = (0xAE + 0x4B + 0x45 + 0x59 + код) & 0xFF`. Код — число. ✓
  (`BirdAirVehicleConnection.sendPasscode`).

Откуда владелец берёт свой код — **не установлено** (может быть напечатан на самокате, зашит,
или выдавался сервером для прокатных). Это барьер доступа самого самоката; подбирать его я не
буду. Если кнопки режима/фары окажутся за этим барьером, страница даст владельцу ввести его
код вручную.

Открытый вопрос: нужен ли этот барьер для **чтения** (начинает ли руль слать статус по `0xFFE1`
после безобидного запроса, или только после кода). Это выясняется запросом `+SVGT=?` на живом
самокате и наблюдением за ответом. ?

## Чего не делаем

- Не писать в OTA/DFU-характеристики и не слать OTA-команды — никогда.
- Не подбирать и не обходить код доступа.
- Запись любых команд в самокат — только при включённом переключателе «Разрешить отправку»
  и по явному действию владельца.
