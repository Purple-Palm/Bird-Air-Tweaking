# Протокол Bird Air (VA00020) — что известно

Разобрано из открытой распакованной сборки приложения Bird для Android
(`co.bird.android` 4.188, репозиторий `darkneuralnet/red`, формат apktool/smali) и из
реального лога самоката. Это личный самокат владельца; цель — чтение телеметрии и
диагностика. **OTA/DFU команды сюда намеренно не вынесены и в самокат не отправляются.**

Каждая строка ниже помечена: ✓ проверено (по коду приложения или по логу владельца — указано
в скобках), ? требует подтверждения на живом самокате.

## BLE

- Сервис `0xFFE0`, характеристика `0xFFE1` — одна на всё: запись без ответа (write without
  response) и уведомления (notify). ✓ (`GattUuid.smali`: `BIRD_AIR_SERVICE` = `0000ffe0-…`,
  `BIRD_AIR_COMMAND_UUID` = `0000ffe1-…`).
- Модуль — прозрачный UART-мост (Telink TLSR8266 / Wi-linktech WLT8266BM). Руль шлёт в него
  AT-команды для настройки; при подключении без приложения он пересылает их наружу — отсюда
  `AT+SETNAME=…`, `AT+RESET` в логе. ✓ (лог владельца).
- **Шифрования нет.** Для Bird Air `BlePayloadEncryptor` — заглушка: `encrypt`/`decrypt`
  возвращают данные как есть. ✓ (`BlePayloadEncryptor$DefaultImpls`,
  `BleScannedVehicle$payloadEncryptor$1`).
- Запись длиннее 20 байт режется на куски по 16 байт с интервалом ~100 мс. ✓
  (`VehicleConnection$DefaultImpls.writeData`).

## Поток телеметрии по FFE1 (главный источник данных)

Пока телефон ничего не пишет, руль молчит: в логе `logs/20261014-160502-log.json` связь
держалась 4 минуты, по `0xFFE1` пришли только `AT+SETNAME`/`AT+RESET` в первую секунду. После
первой же команды `+…` с телефона руль отвечает эхом и начинает слать кадры UART контроллера,
~11 кадров/с (`logs/20261014-174148-log.json`: после `+MODE=3`). ✓ (лог владельца)

Приложение Bird делает так: подписывается на notify, ждёт 500 мс и шлёт `+SVGT=?`, затем
4 раза запрос версии контроллера; регулярного опроса в приложении нет. ✓
(`Vo3.a()` → `firmwareInquiry`, `BirdAirVehicleConnection.smali:174-222, 391-421`).

Поток идёт **~4,5 с после каждой команды** и замолкает; следующая команда продлевает его ещё на
~4,5 с. Один `+SVGT=?` без команды режима его запускает. ✓ (`logs/20261014-175429-log.json`:
9 команд, после каждой 4,3–5,0 с кадров, после последней — 5,0 с). Поэтому «Живые данные» на
странице шлют `+SVGT=?` раз в 3 с, пока владелец их не выключит.

### Формат кадра

`3A` (`:`) · адрес u8 · команда u8 · длина u8 · данные[длина] · сумма u16 LE · `0D 0A`.
Сумма = (адрес + команда + длина + Σ данных) & 0xFFFF. ✓ (все 268 кадров лога сходятся).
BLE режет кадр на уведомления по 20 байт; изредка теряется ведущий `3A` (кадр приходит сразу
после `0D 0A` предыдущего) — такой кадр восстанавливается по длине, сумме и `0D 0A`.

Смещения ниже — от `3A` (смещение 0), как в поле декодера.

| кадр | смещение | тип | поле | откуда |
| --- | --- | --- | --- | --- |
| `3A 17 00 0D` | 9 | u8, младшие 2 бита | режим: 1 TAKEOFF, 2 GLIDE, 3 FLY (байт `09/0A/0B`) | ✓ лог: меняется ровно по `+MODE=n` |
| `3A 17 00 0D` | 12–14 | u24 BE × 0,1 км | пробег (в логе `00 37 A8` → 1424,8 км) | ✓ код (`yq3.n`, `Bird.distance` в метрах = raw × 100); сверить с экраном ? |
| `3A 18 20 10` | 9–10 | u16 LE × 0,001 В | напряжение (≈39,85 В, проседает при включённой фаре) | ✓ лог |
| `3A 18 20 10` | 11–12 | s16 LE, мА | ток, минус = разряд (−46 мА в покое, ~−100 мА с фарой) | ? масштаб и знак проверить на ходу |
| `3A 18 20 10` | 13–14, 15–16 | u16 LE | вероятно остаток и полная ёмкость, мА·ч (3287 / 4363 = 75 %) | ? |
| `3A 18 20 10` | 17 | u8 | заряд, % (в логе `4B` = 75) | ✓ код (`yq3.n` → `Bird.batteryLevel`) |
| `3A 18 20 10` | 7, 8 | u8 | возможно температуры, °C (24) | ? |

Скорость и коды ошибок приложение из кадров не разбирает; искать по логу поездки с метками.

### Ответы на команды

- `+MODE=n`, `+HLGT=n` — руль повторяет команду эхом. ✓ (лог)
- `+SVGT=?` → `+SVGT=` + один сырой байт; версия dash = байт × 0,01 (в логе `0x30` → 0.48). ✓
  (код `yq3.n`, лог)

## Реклама (manufacturer data)

Приложение умеет брать заряд, режим, пробег и версию из manufacturer-specific данных рекламы
(`Ot4.h` → `BirdAirBleScannedVehicle`: версия u16, заряд u8, режим u8, пробег u32, LE) ✓ — но у
этого самоката в рекламе manufacturer data **нет** (скан nRF Connect: только Flags, FFE0, TX
power, имя). `tools/decode_adv.py` оставлен для других экземпляров.

## Команды

Все управляющие команды Bird Air — короткие ASCII-строки, пишутся в `0xFFE1`. ✓
(`Command.smali`, массивы байт в `<clinit>`):

| действие | байты | строка |
| --- | --- | --- |
| режим TAKEOFF | `2B 4D 4F 44 45 3D 31` | `+MODE=1` |
| режим GLIDE | `2B 4D 4F 44 45 3D 32` | `+MODE=2` |
| режим FLY | `2B 4D 4F 44 45 3D 33` | `+MODE=3` |
| фара выкл | `2B 48 4C 47 54 3D 30` | `+HLGT=0` |
| фара вкл | `2B 48 4C 47 54 3D 31` | `+HLGT=1` |
| версия прошивки дисплея | `2B 53 56 47 54 3D 3F` | `+SVGT=?` |
| версия железа дисплея | `2B 48 56 47 54 3D 3F` | `+HVGT=?` (в приложении не вызывается) |

Режимы и фара — те же, что переключает кнопка на руле; проверено на самокате владельца ✓.

## KEY? и код доступа — только для прошивки, не слать

`AE 4B 45 59 3F D6` («KEY?») и `AE 4B 45 59` + [код, сумма] используются **только мастером
обновления прошивки** (`ZD` = BirdAirOTAUpdate, состояния `CHALLENGE_INITIATED` /
`VERIFYING_PASSCODE` / `PASSCODE_VERIFIED`); код — двузначный ручной ввод в диалоге розничной
прошивки (`z23.Jp`). Для чтения и для режимов/фары не нужен. ✓ (код)

На самокате владельца `KEY?` дал ответ `OK OK OK `, после чего поток кадров остановился, руль
показал гаечный ключ и ошибку 37 до выключения питания ✓ (лог 20261014-174148). Потеря связи
руля с контроллером на ходу может отключить мотор. Страница блокирует любые данные, которые
начинаются с `AE 4B 45 59`.

## Чего не делаем

- Не писать в OTA/DFU-характеристики и не слать OTA-команды, `KEY?` и код доступа — никогда.
- Запись команд в самокат — только по явному действию владельца: кнопки «Управления» (при
  включённом «Разрешить отправку») и «Запросить данные» на приборах (только `+SVGT=?`; сам —
  только если владелец включил «Запрашивать сам при подключении»).
